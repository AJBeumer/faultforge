### Result
`npm test` can never run an integration test by accident, and a test proves it.

### Done when
- [ ] A test loads `vitest.config.ts` and asserts that the `unit` project's include pattern matches no file under `packages/*/test/` and that the `integration` project's include matches nothing under `packages/*/src/`.
- [ ] The test fails if either project's include is widened.
- [ ] `npm run check` stays green.

### Why
The code layout rule says a slow test lives under `packages/<package>/test/` and runs only with `npm run test:integration`. Nothing enforces it; a wrong include pattern would put network tests into `check`.

### Notes
- Extend the existing `vitest.config.test.ts` at the repository root, which already loads the config and asserts both project names. Add the include checks there rather than in a new file.
- `npm test` runs `vitest run --project unit`; `npm run test:integration` runs the integration project.
