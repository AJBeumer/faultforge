# The door to the target, and the guard hook

Part of the [rules for coding agents](../../CLAUDE.md). Each rule is one short bullet there; this page has the detail.

- Every write to the target goes through one door: `npm run target:post -- <kind> ...` (issue-create, issue-edit, issue-comment, pr-create, pr-edit, pr-comment, pr-close, push; see `docs/target-door.md`). Write the title and body to files and pass the files. Run it on its own, from this repo's root. It checks the exact text it sends (giveaway words, private template ids, words addressed to Qodo, and for a push the branch name and every new commit's message and files), then sends it with `gh` or `git`, or exits 2 with the reason. `case:ticket`, `case:pr` and the factory runner use it too.
- A `PreToolUse` hook (`.claude/hooks/guard-target.ts`) lets exactly that command through unread, and refuses every other write aimed at the target without reading it: `gh issue` and `gh pr` writes, any `gh` call that isn't a known read, `gh api` with a method or a field, `curl`, `wget` or `Invoke-WebRequest` sending a body, MCP tools that write, `git push` from or to the target checkout, and any write whose destination it can't read. Reads (`gh pr view`, `gh api` GET, `git fetch`, `git log`) and commits in the target checkout work as usual, but a commit there is still refused while its message, or the checkout's pending content, names the lab or the bug, and Edit and Write content in the checkout is checked the same way. The target's git hooks (installed by `npm run guard:install`) stay as a second layer, for commits and pushes made in this checkout of the target; a push from another clone skips them. What the guard is for, and its known gaps: [the threat model](threat-model.md). If the guard blocks something, use the door or reword it. Don't work around it. Run target-repo actions in their own command, never chained with work in this repo. The hook fails closed: if it crashes or can't read its input, it exits with the blocking code (2) and the reason, and the tool call is refused. Each hook has 15 seconds (`timeout` in `.claude/settings.json`); Claude Code treats a hook that exceeds that as a non-blocking error, so the factory runner checks before every run that both hooks answer in well under that time.
